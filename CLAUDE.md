## Architecture

This is a TanStack Start (React SSR) dashboard for the Invinite financial data API. It uses file-based routing with TanStack Router and server functions for API calls.

### API Layer (`src/lib/api/`)

- **openapi.json**: a copy of the data API's spec (`../invinite-data-api/openapi.json`, produced there by `pnpm gen:openapi`). Copy it over, then `pnpm generate:api`. `pnpm-workspace.yaml` holds pnpm 11's `allowBuilds` (esbuild `true`; `@parcel/watcher`, `msw`, `sharp`, `unrs-resolver` `false` — prebuilt binaries / an unused msw worker): without a decision for every dependency build script pnpm 11 stops with `ERR_PNPM_IGNORED_BUILDS`. A new dependency with a build script needs its own entry
- **schema.d.ts**: Auto-generated TypeScript types from OpenAPI spec. Regenerate with `pnpm run generate:api`
- **types.ts**: Derived response/entity types using the `ApiResponse` helper to extract typed responses from schema
- **client.server.ts**: Creates typed `openapi-fetch` client with Bearer auth
- **server-functions.ts**: TanStack Start server functions (`createServerFn`) with Zod validation. These run on the server and handle API calls
- **queries.ts**: React Query hooks (`useQuery`/`useInfiniteQuery`) that call server functions. Each hook manages API key from store and shows error toasts
- **errors.ts**: `ApiRequestError` (`status`, `code` = the body's `error`, `body`). Every earnings server function throws it via `throwApiError(error, response)`; the shared earnings hook helpers (`useEarningsQuery` / `useEarningsInfinite` in `queries.ts`) revive it on the client (`rethrowApiError` → `fromSerialized`: a server function's thrown Error crosses to the client as a plain `Error` with its own properties) and never retry an API answer (`retryUnlessApiError`). A hook with `errorMessage: null` is status-aware — no toast, the page renders the state: event, transcript, press release, metrics, diff, prosody, price attribution (a 404 is a page state there: `metrics_unavailable`, `diff_unavailable` = first call / not derived, `prosody_unavailable`, `price_attribution_unavailable`), audio, slides, documents, search, live stream (`audio_disabled` / `audio_unavailable` / `media_unavailable` / `search_disabled`) and `/live` (its 15-s refetch would otherwise toast on every failure; the "Live now" strip shows a one-line note). The other earnings hooks toast with their `errorMessage`. The REST plan gate is `403 { error: "Forbidden" }` (`isTierError`; `forbidden_tier` is the WebSocket's code). Non-earnings hooks keep their own pattern (raw `throw error` + `useErrorToast`)
- **Earnings calls**: one server function `getEarnings<Route>` + one hook `useEarnings<Route>` (`…Infinite` for calendar, events, Q&A, extractions, documents) per `/v1/earnings-calls/*` route the dashboard shows; webhooks, analysts and people are CLI-only. A call is picked with `EarningsEventSelector` (`eventId`, or `identifier` + `date` / `year` + `quarter`). `getApiBaseUrl` / `useApiBaseUrl` return the (non-secret) API base URL for the live transcript WebSocket. `useEarningsEvent` refetches every 30 s while `isEarningsEventLiveish` (armed / capturing / captured without a transcript); `useEarningsLive(enabled)`; `useEarningsLiveStream` is never stale and refetches only every 15 s while `not_started` (5 credits per request)

### Earnings helpers (`src/lib/earnings/`)

- **format.ts**: pure `formatCallTime` (company timezone, date only when `call_time_source` is null), `formatFiscalPeriod`, `dateStatusVariant` (Badge variant), `formatMs` (`m:ss` / `h:mm:ss`, = the admin console's `formatClock`), `zonedDate`, `isUpcoming` / `isCallToday` (a date-only row's `scheduled_at` is a placeholder: only its date in `tz` counts), `calendarDefaultWindow` (yesterday … today + 14, New York days) / `calendarWindow` / `orderedWindow` (swap `from > to`), `formatStartedAgo`, `SESSION_LABELS`, `formatBytes`, `formatInstant` (timestamp with time, "—" when absent); tested in `format.test.ts`
- **media-timing.ts**: presigned-URL refresh rules ported from the admin console (`MEDIA_URL_REFRESH_BEFORE_MS` 2 min, `LIVE_STREAM_REFRESH_BEFORE_MS` 5 min, `SIGNED_URL_DEFAULT_TTL_MS`, `urlNeedsRefresh`, `msUntilRefresh`; `formatClock` is `format.ts`' `formatMs`); **use-media-url.ts**: `useMediaUrl({ expiresAt, refetch })` refetches before expiry and once on a media load error. **edgar.ts**: `edgarFolderUrl(cik, accession)`. **transcript.ts**: `toTranscriptView(format, data)` (the spec types `data` as unknown; sections carry `qa_start_ms`), `transcriptPlainText`, `speakerName`, `turnIndexAt` (the turn containing a position), `qaStartTurnIndex` (the first turn at / after `qa_start_ms`). **labels.ts**: metric / direction / period / basis / review / tone / role-group / participation labels (`metricLabel`, `DIRECTION_STYLES`, `roleGroup`: `executive` + `ir_host` = management, `participationKindLabel`, `participationDetailText`), `percent` (0–1 share), `formatDecimal`, `formatSigned`, `formatGuidanceValue` / `formatGuidanceRange` (`usd` / `pct` / `shares` units), `highlightTerms(text, query)` (plain string scan, never a regex from the query). All tested. **scroll-to-turn.ts**: `scrollToTurn(ms, timeoutMs)` scrolls / flashes the Transcript tab's `[data-start-ms]` turn containing `ms`, polling briefly for it; false = no timed turn (DOM, untested)

### Earnings pages (`src/routes/$ticker/earnings-calls/`, `earnings-calendar/`)

- `-components/`: shared pieces — `availability-icons` (the five `has_*` flags; "not available" never says why), `call-status-badge` (`date_status` + Live / Published), `call-time` ("date only" caption), `event-link` (→ `/$ticker/earnings-calls/$eventId` under the call's own symbol), `webcast-link`, `events-table` (react-table + skeleton rows), `live-now-strip` (`/live`, "Live audio" badge from `live_audio`), `live-dot` (the pulsing live dot), `calendar-filters` (`validateCalendarSearch`: every search field optional, invalid values fall back, `from > to` swapped; event type omitted = the API's default `earnings_call`, "All events" = `event_type=all`), `event-type-badge` (the type of a non-earnings event; calendar, company calls — whose `/events` answers every type by default — and the call header)
- The calendar sends all five statuses for "All statuses" (omitted, the API drops cancelled calls); `now` is taken once per mount with a lazy `useState` initializer

### Call page (`src/routes/$ticker/earnings-calls/$eventId/`)

- Transcript tab: `qa_start_ms` (top level of every format; sections also in `data`) → "Q&A starts at m:ss" (`QaStart`, a seek button) in the meta line, on the Sections' Q&A header and as a Q&A divider above the first Q&A turn of Speakers / Cleaned
- `?tab=` (`validateSearch`, optional, unknown → transcript; values `CALL_TAB_VALUES` in `-components/call-tabs.tsx`). The page is keyed by `eventId`; `$ticker` is informational (a symbol mismatch still renders); an invalid id or a 404 → `NotFound`
- `call-tabs.tsx`: `CALL_TABS` (label, `has_*` flag, render) — only the active panel is mounted, so an unselected tab sends no request; a `has_*: false` tab shows a muted label and "Not available for this call". Add a tab there. The derived tabs (`tabs/guidance-tab` → `guidance-table` / `kpi-table` / `guidance-history-panel`, `qa-tab`, `participants-tab`, `metrics-diff-tab`, `prosody-tab`, `price-attribution-tab`) have no `has_*` flag: an underived call shows each tab's empty state. Guidance `review` "needs review" filters the loaded rows (the API filters `approved | auto | all` only); the history dialog is scoped to the clicked item's period kind + basis
- "Price moves" (`?tab=price-moves`, `tabs/price-attribution-tab.tsx`, `useEarningsPriceAttribution` → `GET /v1/earnings-calls/price-attribution`): the coincidence sentence as lead text (temporal coincidence, not attribution of cause), anchor facts (anchor kind, lag, uncertainty, market session, bar count, end-of-window return), the largest minute moves with their utterances, a cumulative-return line (`ChartFrame` from `src/components/status/chart-parts.tsx`) and the bucket table (minute in New York time, return / cumulative in bps, utterance refs as `SeekButton`s). Derived returns only — the response has no price or volume field and the tab shows none. `404 price_attribution_unavailable` (no minute row yet) → `Notice`. While the call is live (`live: true`, `settled: false`, live-price-feed task 9) the answer holds the minute rows so far with a null summary: a "Live — minute rows so far, not settled" `Notice`, no anchor facts (`hasSummary`) and no top minutes; `PriceAttributionTab` passes `{ live: isEarningsEventLiveish(event) }` → `useEarningsPriceAttribution` refetches every 60 s (same query key as the live player's seed). `PriceAttributionView` (data / error / isLoading) is the pure body, tested in `src/routes/-tests/price-attribution-tab.test.tsx`
- Audio host (`audio-context.tsx` + `audio-player.tsx` + `mini-player.tsx`): the page's one `<audio>` element sits between the tab bar and the panel, hidden off the Audio tab; `/audio` is requested the first time the Audio tab opens OR a timestamp is clicked (`requested`; never on page load — an empty selector keeps the query idle before). `useCallAudio().seekMs` (null only when the call has no recording and no search hit plays) is what every `SeekButton` (`seek-button.tsx`: button / text / nothing for a null `start_ms`; transcript turns, the Q&A start and the derived tabs alike) calls: before the recording is in, the click is kept (`pendingSeekRef`) and played once the source is set. `loaded` = a recording is in the element; `skip` / `setPlaybackRate` drive the player bar. `playUrl(url)` loads a search hit's `audio_url` (positioned by its `#t=` fragment) into the same element — `AudioPlayer` renders it for `playedUrl` while `/audio` is idle, and `seekMs` then seeks it; "Play from here" seeks only a loaded recording, else plays the hit's URL (no extra `/audio` request). `MiniPlayer` (sticky, outside the Audio tab, once `requested` or `loaded`): play / pause, position, loading / failed state, a button to the Audio tab. The provider owns the element's src (set imperatively) so a refreshed presigned URL swaps in at the same position, playing or paused
- Following the recording with its text (2026-10-10, the replay twin of the live player's follow mode): once a recording is `loaded` the provider asks for the `format=words` transcript ONCE (`useCallAudio().words` / `wordTurns`, `toWordTurns`); `useCallPlayback()` (`src/lib/earnings/use-playback-position.ts`: media events + a `requestAnimationFrame` loop while playing) is subscribed by each consumer, never by the provider. `tabs/follow-along.tsx` (`FollowAlong`, under the Audio tab's note): every turn, the heard one highlighted and kept in view (`scrollIntoView`, paused by a wheel / touch scroll, "Follow the audio" resumes), its words lit as spoken, said text plain, upcoming text faint; a turn's timestamp seeks; only the active turn re-renders at word rate (`React.memo`). `caption-line.tsx` (`CaptionLine`, a port of the admin console's `CallCaptionLine.tsx`, under the player bar and as the mini-player's last row): one gliding row, the spoken word centred (transform, chunked window). `active-turn-bridge.tsx` marks the Transcript tab's heard turn (`data-active` on `[data-turn-index]`, by the DOM, no scroll). Pure pieces in `src/lib/earnings/follow-along.ts` (`timedWordsOf` spreads an untimed turn to the next turn's start, `buildCaptionWords`, `indexAt`, `activeTurnIndex`, `captionWindow`; tested)
- `media-state.tsx`: `MediaState` renders `audio_disabled` / `audio_unavailable` / `media_unavailable` / the plan gate / a 404 as a `Notice`, anything else as `ErrorState`
- `ask-this-call.tsx`: `AskThisCall({ scope })` — `event` (call page, above the tab bar: "Play from here" seeks the loaded recording or `playUrl`s the hit, else "Jump to transcript" = tab switch + a `TranscriptJump` `{ ms, nonce }` the page hands the Transcript tab through `CallTabProps.transcriptJump`: once its answer is in, Sections / Plain text / a 404 cleaned layer switch to Speakers, then `scrollToTurn`; an untimed transcript or a passage not found → a `toast.info` notice, never silence; `onTranscriptJumpHandled` clears it) or `company` (the calls list: hits link to their call, audio / slide open in a new tab). Runs on submit; a type chip re-runs the submitted question; `search_disabled` / 429 / `search_unavailable` / plan gate render as notices
- `live-player-slot.tsx`: mounts `live/live-player.tsx` above the tabs while `capture_status === "capturing"` or the call is in `/live` (asked only while `isEarningsEventLiveish`); sticky for the page's life (the ended note stays until the Transcript tab has the final transcript); no stored key → "Enter your API key to follow this call live". See "Live earnings calls"
- Presigned URLs (audio, slides, documents) are bearer credentials: never in the router search or logs; links use `rel="noreferrer"`. The PDF viewer keeps the URL it opened with

### Live earnings calls (`src/lib/live/`, `-components/live/`)

- **Browser WebSocket (owner decision 2026-10-09)**: `use-live-transcript.ts` opens `wss://<api>/v1/ws?api_key=<stored key>` itself (`liveWsUrl`) — the one place the key leaves the server functions: Netlify cannot hold a server-side socket and the key already lives in localStorage. Never log that URL. A key change (`apiKeyUpdatedAt`) reopens the socket; unmount unsubscribes and closes it
- **WS flow**: `subscribe { event_id, since_seq, partials: true, prices: true }` (`since_seq` = the reducer's `lastSeq`, `-1` first: the API replays every final, no REST backlog); the API reorders finals and sends a `gap` frame before each jump (accepted, never re-subscribed; late finals still arrive); reconnect backoff 1 s → 30 s × 10 resumes from `lastSeq`; `attach_failed` / `unavailable` re-subscribe after 10 s; `resume_unavailable` is a note (live delivery continues); admission closes 4001 / 4003 / 4029 and `forbidden_tier` / `not_live` / `not_found` / `subscription_limit` / `bad_message` are final. No JSON ping (IDA answers it with `bad_message`): 60 s without a frame = the "stalled" pill only — every frame re-arms that timer EXCEPT `price_tick` (a tick a second would hide a stopped transcript). Frame schemas in `ws-frames.ts` mirror IDA `src/routes/websocket/types/earningsMessages.ts`
- **Ported from the admin console** (`../invinite/admin-dashboard/src/components/earnings-calls/`, keep in step): `live-transcript-reducer.ts` (local `LiveSpeakerAssignment` instead of the admin DTO) and `position-to-call-ms.ts`, each with its suite; `media-timing.ts` was ported by the call page into `src/lib/earnings/` (`LIVE_STREAM_REFRESH_BEFORE_MS`). `use-live-audio.ts`, `use-live-transcript.ts`, `live-player.tsx`, `live-transcript-view.tsx` are modelled on the admin ones, not copied (WS instead of Ably + BFF)
- **hls.js `1.7.3`, pinned** (`live-clients.ts`: lazy `loadHls`, `LIVE_HLS_CONFIG` = the admin values). `use-live-audio.ts`: 404 → ended, 403 → one fresh URL + reload at position, other fatal errors one recovery; a new URL is adopted only through `reload()` before the loaded one expires; buffering pill past 5 s, one reload of loading past 20 s; the `<audio>` is held in a ref (always mounted by `LivePlayer`)
- **Credits**: each `GET /v1/earnings-calls/live/stream` costs 5 — requested only for a call with `live_audio`, every 15 s while `not_started`, before the loaded URL expires and once on a 403 (said in the player's Diagnostics too)
- **Sync**: `callMs = positionToCallMs(playingDate, call_t0)`; at the edge while playing the text is held back to it (`liveTurns(…, callMs)`); > 10 s behind = follow mode (heard turn highlighted, click seeks)
- **Live price line** (tasks/inhouse-live-price-feed task 9): `price_tick` frames (≤ 1 / s, only seconds with a trade; `priceTickFrameSchema` / `toPriceTick` in `ws-frames.ts`, mirroring IDA's `PriceTickFrame`) → `live-prices-reducer.ts` (`livePricesReducer`: ordered by `at`, a second seen again replaces its tick, ≤ 7,200 held, newest non-null `reference` / `prevClose`), returned by `useLiveTranscript` as `prices`. No second-level backlog exists: `LivePlayer` seeds the line from the price-attribution minute rows while `live` (`useEarningsPriceAttribution(…, { live })`, every 60 s; a 404 = none yet). `live/live-price-chart.tsx` (`LivePriceChart`, `ChartFrame` 160 px, return bps ↔ price toggle, lead text "Temporal coincidence, not attribution of cause. Pre-market and after-hours bars are sparse.") between the audio and the transcript, "No price ticks yet." without ticks or rows; Diagnostics counts ticks and minute rows. Pure pieces in `live/live-price-chart-data.ts` (another basename than the component on purpose; tested): `clockOffsetMs` (call t0 = a tick's `at − call_ms`, else the stream's `call_t0`, else wall time), `mergeSeed` (a minute row = one point at its close, cumulative return vs the same reference as the ticks; rows from the first tick on dropped), `gapBreaks` (> 5 s between ticks / > 90 s next to a minute point = a break row; an `isolated` point gets a dot), `formatCallMs`. The cursor `ReferenceLine` marks the audio position while it plays (call clock only). Ticks that arrive after `call_ended` are not shown (the socket closes 5 s later). Component test `src/routes/-tests/live-price-chart.test.tsx` (point / gap counts in the chart's `aria-label`)

### Status page (`src/routes/status.tsx`, `src/components/status/`, `src/lib/status/`)

- Public, key-less `/status` (task 21): `GET /status` families + freshness and `GET /status/earnings-calls` (the pipeline's SLO payload + IDA's `windowDays` / `coverageDays` / `summary` / `keywordHitDays`). `chart-data.ts` builds every chart row on the window's day axis with `null` for a day without a value (a gap, never a zero); `earningsDayPoints(days, vendor, windowDays, keywordHitDays)` joins the per-vendor SLO rows with the API-measured keyword-hit latency by day (`keywordHitP50S` / `keywordHitP95S` in seconds, `null` without hits; `hits = 0` counts as none). `earnings-section.tsx` draws "speech → keyword hit" p95 next to "speech → live segment" on the live-latency chart, a "Keyword hit p95" day-table column and a 7-day tile, each with the note from `labels.ts` (`LATENCY_SERIES_LABELS`, `KEYWORD_HIT_LATENCY_NOTE`: measured inside the API process, excludes the client's network)

### Routing (`src/routes/`)

File-based routing with TanStack Router. The route tree is auto-generated in `routeTree.gen.ts`.

- `__root.tsx`: Root layout with SidebarProvider and Toaster
- `index.tsx`: Landing page with API key input
- `$ticker/route.tsx`: Layout for all company routes with sidebar navigation
- `$ticker/*.tsx`: Company-specific pages (filings, financials, dividends, etc.)

### State Management

- **API Key**: Zustand store in `src/lib/stores/api-key-store.ts` persists to localStorage (`invinite-data-api-key`). Handles SSR hydration with `hasHydrated` flag
- **Ticker History**: `src/lib/stores/ticker-store.ts` for recent ticker navigation

### UI Components (`src/components/ui/`)

Base UI components built on `@base-ui/react` primitives with `class-variance-authority` for variants. Uses `cn()` utility from `src/lib/utils.ts` (clsx + tailwind-merge).

### Environment

- `INVINITE_DATA_API_KEY`: Server-side API key (optional, can be set via UI)
- `INVINITE_DATA_API_URL`: API base URL (defaults to https://data.invinite.com)

Validated with `@t3-oss/env-core` in `src/lib/env.ts`.
