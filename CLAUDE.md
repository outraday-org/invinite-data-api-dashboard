## Architecture

This is a TanStack Start (React SSR) dashboard for the Invinite financial data API. It uses file-based routing with TanStack Router and server functions for API calls.

### API Layer (`src/lib/api/`)

- **openapi.json**: the pinned data API spec, adopted from the API's versioned `reference/openapi.json` (see "Data contract ownership"). Copy it over, then `pnpm generate:api` (its output is committed after `pnpm run check`'s `eslint --fix`, which re-sorts it). `pnpm-workspace.yaml` holds pnpm 11's `allowBuilds` (esbuild `true`; `@parcel/watcher`, `msw`, `sharp`, `unrs-resolver` `false` — prebuilt binaries / an unused msw worker): without a decision for every dependency build script pnpm 11 stops with `ERR_PNPM_IGNORED_BUILDS`. A new dependency with a build script needs its own entry
- **schema.d.ts**: Auto-generated TypeScript types from OpenAPI spec. Regenerate with `pnpm run generate:api`
- **types.ts**: Derived response/entity types using the `ApiResponse` helper to extract typed responses from schema
- **client.server.ts**: Creates typed `openapi-fetch` client with Bearer auth
- **server-functions.ts**: TanStack Start server functions (`createServerFn`) with Zod validation. These run on the server and handle API calls
- **queries.ts**: React Query hooks (`useQuery`/`useInfiniteQuery`) that call server functions. Each hook manages API key from store and shows error toasts
- **errors.ts**: `ApiRequestError` (`status`, `code` = the body's `error`, `body`). Every earnings server function throws it via `throwApiError(error, response)`; the shared earnings hook helpers (`useEarningsQuery` / `useEarningsInfinite` in `queries.ts`) revive it on the client (`rethrowApiError` → `fromSerialized`: a server function's thrown Error crosses to the client as a plain `Error` with its own properties) and never retry an API answer (`retryUnlessApiError`). A hook with `errorMessage: null` is status-aware — no toast, the page renders the state: event, transcript, press release, stats, comparison, prosody, price attribution (a 404 `not_found` is a page state there: not derived yet / first call, the reason in `detail`), audio, slides, investor documents / document search, transcript search, live audio (403 `forbidden` = audio refused, 503 `unavailable` = media outage / search off) and the live list (its 15-s refetch would otherwise toast on every failure; the "Live now" strip shows a one-line note). The other earnings hooks toast with their `errorMessage`. The REST plan gate is the `403` problem `plan_required` (the legacy `403 { error: "Forbidden" }` is still read) (`isTierError`; `forbidden_tier` is the WebSocket's code). A v2 problem+json body is read too (see "Data API v2"). Non-earnings hooks keep their own pattern (raw `throw error` + `useErrorToast`)
- **Earnings calls**: every earnings page reads the events family (see "Data API v2"); no old `/v1/earnings-calls/*` server function or hook is left (webhooks, analysts and people are CLI-only). `getApiBaseUrl` / `useApiBaseUrl` return the (non-secret) API base URL for the `/v1/stream` WebSocket. `useV2Event` refetches every 30 s while `isEarningsEventLiveish` (armed / capturing / captured without a transcript); `useV2LiveEvents(enabled)`; `useV2LiveAudio` is never stale and refetches only every 15 s while `not_started`

### Live earnings calls (`src/lib/live/`, `-components/live/`)

- **Browser WebSocket (owner decision 2026-10-09)**: `use-live-transcript.ts` opens `wss://<api>/v1/stream?api_key=<stored key>` itself (`liveWsUrl`; `/v1/ws` was deleted 2026-11-11 — the stream is the same session with the channels `events.live` (was `earnings-calls.live`) and `news` (was `news.live`)) — the one place the key leaves the server functions: Netlify cannot hold a server-side socket and the key already lives in localStorage. Never log that URL. A key change (`apiKeyUpdatedAt`) reopens the socket; unmount unsubscribes and closes it
- **WS flow**: `subscribe { channel: "events.live", event_id, since_seq, partials: true, prices: true }` (`since_seq` = the reducer's `lastSeq`, `-1` first: the API replays every final, no REST backlog); the API reorders finals and sends a `gap` frame before each jump (accepted, never re-subscribed; late finals still arrive); reconnect backoff 1 s → 30 s × 10 resumes from `lastSeq`; `attach_failed` / `unavailable` re-subscribe after 10 s; `resume_unavailable` is a note (live delivery continues); admission closes 4001 / 4003 / 4029 and `forbidden_tier` / `not_live` / `not_found` / `subscription_limit` / `bad_message` are final. No JSON ping (IDA answers it with `bad_message`): 60 s without a frame = the "stalled" pill only — every frame re-arms that timer EXCEPT `price_tick` (a tick a second would hide a stopped transcript). Frame schemas in `ws-frames.ts` mirror IDA `src/routes/websocket/types/earningsMessages.ts`
- **Ported from the admin console** (`../invinite/admin-dashboard/src/components/earnings-calls/`, keep in step): `live-transcript-reducer.ts` (local `LiveSpeakerAssignment` instead of the admin DTO) and `position-to-call-ms.ts`, each with its suite; `media-timing.ts` was ported by the call page into `src/lib/earnings/` (`LIVE_STREAM_REFRESH_BEFORE_MS`). `use-live-audio.ts`, `use-live-transcript.ts`, `live-player.tsx`, `live-transcript-view.tsx` are modelled on the admin ones, not copied (WS instead of Ably + BFF)
- **hls.js `1.7.3`, pinned** (`live-clients.ts`: lazy `loadHls`, `LIVE_HLS_CONFIG` + `SYNCED_HLS_CONFIG` = the admin values). `use-live-audio.ts`: 404 → ended, 403 → one fresh URL + reload at position, other fatal errors one recovery; a new URL is adopted only through `reload()` before the loaded one expires; buffering pill past 5 s, one reload of loading past 20 s; the `<audio>` is held in a ref (always mounted by `LivePlayer`)
- **Credits**: each `GET /v1/events/{event_id}/live-audio` is billed — v2 has no `live_audio` flag, so it is asked for every live call (`disabled` = no live audio), every 15 s while `not_started`, before the loaded URL expires and once on a 403 (said in the player's Diagnostics too)
- **Synced / Live audio** (backend earnings `tasks/X-inhouse-kyutai-live-quality-2026-10-31` task 5): the transcript is released ≈ 8 s + STT latency behind the capture, so the player holds the AUDIO back to the text. `live-sync.ts` is the rule, pure and tested, a byte-identical twin of the admin console's and the invinite app's `live-sync.ts` (change all three): `audioCallMs ≤ newestFinal.endMs − 1500`, 0.9× past it, a pause past it by 3 s ("waiting for the transcript"), a forward jump 20 s behind it (landing on the newest final's start). Only finals move the point; partials are revealed by the audio (`liveTurns(…, callMs)`) and never move it. No new final for 25 s = the audio plays on. Synced is the default (`resolveLiveMode`; a refused transcript = Live audio, no toggle), persisted under `invinite-data-api-live-mode`. An explicit seek behind the point is follow mode (heard turn highlighted, click seeks) until the audio is back or "Back to synced"; the only automatic seek is the forward jump. `SYNCED_HLS_CONFIG`: `liveSyncDuration` 12, then `hls.targetLatency` = edge − newest final's start + 1.5 s, no count fields (hls.js refuses a mix), `liveMaxLatencyDuration` 24 h (its own 30-s jump would throw a held audio past the text). A Synced "Tune in" starts at the measured distance (the first playlist, `Hls.Events.LEVEL_LOADED`), or the audio starts ahead of the text and sits through a long pause. Live audio keeps hls.js's 30-s jump for a player that fell behind; "From the beginning" and an explicit seek lift it (`keepListenerPlace`) until the audio is back at the edge. `position.behindS` is relative to hls.js's sync position; the true distance is `edgeBehindS`. Live audio: > 10 s behind = follow mode, text as released ("transcript ≈ N s behind")
- **Live price line** (tasks/inhouse-live-price-feed task 9): `price_tick` frames (≤ 1 / s, only seconds with a trade; `priceTickFrameSchema` / `toPriceTick` in `ws-frames.ts`, mirroring IDA's `PriceTickFrame`) → `live-prices-reducer.ts` (`livePricesReducer`: ordered by `at`, a second seen again replaces its tick, ≤ 7,200 held, newest non-null `reference` / `prevClose`), returned by `useLiveTranscript` as `prices`. No second-level backlog exists: `LivePlayer` seeds the line from the price-attribution minute rows while `live` (`useV2PriceAttribution(…, { live })`, every 60 s; a 404 = none yet). `live/live-price-chart.tsx` (`LivePriceChart`, `ChartFrame` 160 px, return bps ↔ price toggle, lead text "Temporal coincidence, not attribution of cause. Pre-market and after-hours bars are sparse.") between the audio and the transcript, "No price ticks yet." without ticks or rows; Diagnostics counts ticks and minute rows. Pure pieces in `live/live-price-chart-data.ts` (another basename than the component on purpose; tested): `clockOffsetMs` (call t0 = a tick's `at − call_ms`, else the stream's `call_t0`, else wall time), `mergeSeed` (a minute row = one point at its close, cumulative return vs the same reference as the ticks; rows from the first tick on dropped), `gapBreaks` (> 5 s between ticks / > 90 s next to a minute point = a break row; an `isolated` point gets a dot), `formatCallMs`. The cursor `ReferenceLine` marks the audio position while it plays (call clock only). Ticks that arrive after `call_ended` are not shown (the socket closes 5 s later). Component test `src/routes/-tests/live-price-chart.test.tsx` (point / gap counts in the chart's `aria-label`)
